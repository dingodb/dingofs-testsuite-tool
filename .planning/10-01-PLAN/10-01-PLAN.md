# Phase 10: 结果解析与保存

## Plan 10-01: 解析并保存集成测试结果

**Objective:** Parse integration test results from the automation framework and save them to the output directory

**Requirements Addressed:**
- INTG-04: 解析自动化框架测试结果
- INTG-05: 保存结果到指定输出目录
- AUTO-03: 提供 --help 显示集成测试帮助信息

**Success Criteria:**
1. Automation framework output is parsed to identify success/failure
2. Results are saved to `$OUTPUT/integration/` directory
3. result.log correctly records integration test results

---

## Background

The automation framework (`run_tests.py`) produces:
1. Test summary output (to stdout): `Total Cases: X, Passed: Y, Failed: Z, Skipped: W`
2. Allure results in `allure-results/` directory
3. Exit code based on test failures

Current issues:
- `log_result()` for 'int' tool doesn't parse the output, just uses exit code
- Results are not being copied to the OUTPUT directory
- `--help` for int tool already exists from Phase 8 (AUTO-03 partially met)

## Task 1: 更新 integration_run() 保存结果并解析

### Action
更新 `integration_run()` 函数以正确保存结果并解析测试输出。

**Read first:**
- `/mnt/disk5/daigy/dingofs-testsuite-tool/entrypoint.sh` (integration_run function)
- `/mnt/disk5/daigy/dingofs-testsuite-tool/dingofs-integration-test/run_tests.py` (查看报告目录参数)

**具体修改:**

在 integration_run() 函数中，修改运行命令以使用 OUTPUT/integration 作为报告目录，并捕获解析测试结果:

1. 修改报告目录为 OUTPUT/integration/allure-results:

```bash
    # Create output directory with allure-results subdirectory
    mkdir -p "$OUTPUT"
    mkdir -p "$OUTPUT/integration"
    mkdir -p "$OUTPUT/integration/allure-results"
```

2. 修改运行命令使用正确的报告目录:

```bash
    # Run tests with dynamic environment and proper report directory
    cd "$INTEGRATION_DIR"
    python3 run_tests.py "$module" --env env_dynamic --skip-setup \
        --report-dir "$OUTPUT/integration/allure-results" 2>&1 | tee "$log_file"
    local exit_code=${PIPESTATUS[0]}
```

3. 添加结果解析逻辑（在运行之后，exit_code 获取之后）:

```bash
    # Parse test results from the log output
    local int_passed=0
    local int_failed=0
    local int_total=0

    # Extract test statistics from log (format: "Passed: X", "Failed: Y", "Total Cases: Z")
    if grep -q "Passed:" "$log_file"; then
        int_total=$(grep "Total Cases:" "$log_file" | sed 's/.*Total Cases: //' | sed 's/ .*//' || echo "0")
        int_passed=$(grep "Passed:" "$log_file" | sed 's/.*Passed: //' | sed 's/ .*//' || echo "0")
        int_failed=$(grep "Failed:" "$log_file" | sed 's/.*Failed: //' | sed 's/ .*//' || echo "0")
    fi

    echo ""
    echo "=========================================="
    echo "Integration Test Summary:"
    echo "  Total: $int_total"
    echo "  Passed: $int_passed"
    echo "  Failed: $int_failed"
    echo "=========================================="
    echo ""

    # Determine success based on parsed results
    local status="FAIL"
    if [[ "$int_failed" == "0" ]] && [[ "$int_total" -gt "0" ]]; then
        status="SUCCESS"
    fi

    # Set details string for log_result
    local details="Total: $int_total, Passed: $int_passed, Failed: $int_failed"
```

### Acceptance Criteria
- integration_run() uses --report-dir to save allure results to OUTPUT/integration/allure-results
- Test summary (passed/failed/total) is parsed from the log output
- Status is determined based on parsed results (not just exit code)

```bash

                # Try to find passed/failed counts from log
                local passed_count=$(grep -h "Passed:" "$output_dir"/int_*.log 2>/dev/null | tail -1 | sed 's/.*Passed: //' | sed 's/[^0-9].*//' || echo "0")

                    status="SUCCESS"
                    details="Integration tests passed (Passed: ${passed_count:-0}, Failed: ${failed_count:-0})"
                elif [[ -n "$failed_count" ]] && [[ "$failed_count" -gt "0" ]]; then
                    status="FAIL"
                    details="Integration tests failed (Passed: ${passed_count:-0}, Failed: ${failed_count:-0})"
                fi
            fi
            ;;
```

然后在 details 输出部分，确保 int 的 details 被正确输出。

### Acceptance Criteria
