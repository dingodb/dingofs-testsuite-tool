# Phase 9: 参数传递与执行

## Plan 09-01: MDSADDR 传递到自动化框架

**Objective:** MDS address from `dtt config` is passed to the automation framework and tests execute successfully

**Requirements Addressed:**
- INTG-02: 创建 `integration_run()` 函数执行自动化框架 (Already done in Phase 8, verify it works)
- INTG-03: 从 `dtt config` 获取 MDS 地址并传递到自动化框架
- AUTO-02: 配置自动化框架运行环境

**Success Criteria:**
1. MDSADDR is read from `dtt config mdsaddr` and passed to container via docker -e flag
2. integration_run() correctly passes MDSADDR to the automation framework
3. The automation framework uses the provided MDS address instead of hardcoded values

---

## Background

The automation framework (`run_tests.py`) loads environment configurations from:
1. `conf/env/*.yaml` files (按字母序合并)
2. `conf/env_*.yaml` 根目录文件

The framework uses `parse_environment(env_name)` which loads from these YAML files. We need to create a dynamic environment file at `conf/env/env_dynamic.yaml` with the MDS address from `dtt config`.

## Task 2: 简化 integration_run() 的模块和参数

### Action
当前 integration_run() 使用硬编码的 `--env env_126_quota`，需要改为使用动态创建的 `env_dynamic`。

**具体修改:**

在 integration_run() 中，删除或注释掉旧的 hardcoded env_126_quota 引用，统一使用动态环境。

确保完整的 integration_run() 函数如下:

```bash
integration_run() {
    echo "Running DingoFS Integration Tests..."
    echo "  Module: $SCENARIO"
    echo "  Mount: $MOUNT"
    echo "  Output: $OUTPUT"
    echo ""

    # Get MDS address from environment
    local mdsaddr="${MDSADDR:-}"
    if [[ -z "$mdsaddr" ]]; then
        echo "Error: MDSADDR environment variable not set"
        echo "Please set MDS address via: dtt config set mdsaddr <address>"
        exit 1
    fi

    # Create output directory
    mkdir -p "$OUTPUT"
    mkdir -p "$OUTPUT/integration"

    local start_time=$(date +"%Y-%m-%d %H:%M:%S")
    local timestamp=$(date +"%Y%m%d_%H%M%S")
    local log_file="$OUTPUT/integration/int_${timestamp}.log"

    # Create dynamic environment config in the framework's conf directory
    local dynamic_env_dir="$INTEGRATION_DIR/conf/env"
    local dynamic_env_file="$dynamic_env_dir/env_dynamic.yaml"

    mkdir -p "$dynamic_env_dir"
    cat > "$dynamic_env_file" << EOF
env_dynamic:
  mds_addr: ${mdsaddr}
  webhook_url: ''
  clients:
  - host: localhost
    mount_path: ${MOUNT}
    fs_name: fs-test
    dingo_tool_path: /usr/local/bin/dingo
    client_count: 1
    client_conf:
      mds.addr: ${mdsaddr}
  remote_caches: []
  storage:
    storage_type: s3
    storage_env: minio
EOF

    echo "Using MDS address: $mdsaddr"
    echo "Dynamic env file: $dynamic_env_file"
    echo ""
    echo "Log file: $log_file"
    echo ""

    # Run the integration test framework
    # Default module is quota if not specified
    local module="${SCENARIO:-quota}"

    cd "$INTEGRATION_DIR"

    # Run tests with dynamic environment
    python3 run_tests.py "$module" --env env_dynamic --skip-setup 2>&1 | tee "$log_file"
    local exit_code=${PIPESTATUS[0]}

    echo ""
    echo "Integration tests completed with exit code: $exit_code"
    echo "Log saved to: $log_file"

    # Log result
    log_result "int" "$module" "$exit_code" "$start_time" "$OUTPUT"

    exit $exit_code
}
```

### Acceptance Criteria
- integration_run() uses `env_dynamic` instead of `env_126_quota`
- Dynamic env file is created with correct MDS address
