<task type="auto">
  <name>Task 1: Create Dockerfile with all storage testing tools</name>
  <files>Dockerfile</files>
  <read_first>
    - .planning/phases/01-docker-image-construction/01-CONTEXT.md (user decisions D-01 through D-06)
  </read_first>
  <behavior>
    - Dockerfile uses ubuntu:24.04 as base image
    - fio installs successfully via apt-get
    - JRE (not JDK) installs via apt-get for vdbench
    - vdbench jar downloads to /opt/vdbench/vdbench.jar
    - mdtest installs via apt-get
    - apt cache cleaned after installations
  </behavior>
  <action>
Create a Dockerfile in the project root with the following structure:

1. **Base image**: `FROM ubuntu:24.04`

2. **Install system dependencies and tools in single RUN layer** (per D-05 single-stage build):
   - Update apt: `apt-get update`
   - Install fio: `apt-get install -y fio` (per D-01)
   - Install JRE only (not JDK): `apt-get install -y default-jre-headless` (per D-03 — headless JRE is smaller)
   - Install mdtest: `apt-get install -y mdtest` (per D-04)
   - Install wget for downloading vdbench: `apt-get install -y wget`
   - Create vdbench directory: `mkdir -p /opt/vdbench`
   - Download vdbench jar: `wget -q https://oracle.com/technetwork/server-storage/vdbench-downloads-1901681.html/vdbench50407.zip -O /tmp/vdbench.zip` (use actual Oracle download URL or mirror if available; if not, use a placeholder URL and document where to get vdbench)
   - Extract and place jar: Note that vdbench distribution is a zip containing the jar
   - Clean up: `apt-get clean && rm -rf /var/lib/apt/lists/* /tmp/vdbench.zip` (per D-06)

3. **Set working directory**: `WORKDIR /data`

4. **Default command**: `CMD ["/bin/bash"]`

IMPORTANT implementation notes:
- vdbench from Oracle requires accepting license agreement; use the direct download URL pattern or document the manual download requirement
- For vdbench, the typical distribution is vdbench50407.zip or similar; inside is vdbench.jar
- Combine all apt operations in single RUN to minimize image layers
- Use `default-jre-headless` instead of `default-jre` to avoid GUI dependencies
- The exact vdbench download URL may need adjustment based on Oracle's current distribution method

Alternative for vdbench if Oracle URL is problematic:
- Create /opt/vdbench directory
- Add a comment in Dockerfile explaining vdbench must be downloaded manually from Oracle and placed at /opt/vdbench/vdbench.jar
- Or use a known mirror if available
  </action>

  </verify>
